## 二、后端技术：Django 框架

### 2.1 项目结构与 MTV 模式

Django 采用经典的 **MTV（Model-Template-View）** 架构模式。在本项目中，MTV 的具体映射关系如下：

- **Model（模型层）**：定义在 `testcase/models.py` 中，封装所有数据库表结构。
- **Template（模板层）**：前端由 Vue 承担，Django 本身不渲染 HTML 模板。
- **View（视图层）**：定义在 `testcase/views.py` 中，处理所有 HTTP 请求并返回 JSON 响应。

Django 项目的入口配置文件位于 `testui/` 目录下：

```python
testui/
├── settings.py      # 全局配置（INSTALLED_APPS、MIDDLEWARE、数据库等）
├── urls.py          # 根路由：将 URL 模式分发给各 App 的 urls.py
├── routing.py       # WebSocket 路由配置
├── asgi.py          # ASGI 入口（支持 HTTP + WebSocket 共存）
├── wsgi.py          # WSGI 入口（纯 HTTP）
└── celery.py        # Celery 异步任务配置
```

### 2.5 DRF ViewSet 与业务逻辑

Django REST Framework 的 **ViewSet** 是本项目 API 层的核心抽象。它将一组相关的视图操作（list、create、retrieve、update、destroy）封装在一起，由 DRF 的 `Router` 自动生成 URL。

#### 2.5.1 TestcaseViewSet — 标准 CRUD

```python
# testcase/views.py
class TestcaseViewSet(viewsets.ModelViewSet):
    """标准 RESTful ViewSet，提供完整的增删改查接口"""
    queryset = TestcaseType.objects.all()
    serializer_class = TestcaseSerializer
    filter_backends = [django_filters.rest_framework.DjangoFilterBackend]

    def get_queryset(self):
        msg_type = self.request.query_params.get('msg_type')
        msg_name = self.request.query_params.get('name')
        # 支持按消息类型、名称等条件过滤
        return self.queryset.all()
```

该 ViewSet 继承自 `ModelViewSet`，因此自动具备 `list()`、`create()`、`retrieve()`、`update()`、`destroy()` 五个标准方法，无需手动编写每个视图函数。

### 2.6 WebSocket 实时通信

Django Channels 将 Django 从纯同步 HTTP 服务器扩展为支持 **ASGI（异步服务器网关接口）** 的框架，能够同时处理 HTTP 请求和 WebSocket 连接。

#### ASGI 入口配置

```python
# testui/asgi.py
import os
from channels.auth import AuthMiddlewareStack
from channels.routing import ProtocolTypeRouter, URLRouter
from channels.security.websocket import AllowedHostsOriginValidator
from django.core.asgi import get_asgi_application

os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'testui.settings')

application = ProtocolTypeRouter({
    # HTTP 请求仍由 Django 处理
    "http": get_asgi_application(),
    # WebSocket 请求交给 Channels 处理
    "websocket": AllowedHostsOriginValidator(
        AuthMiddlewareStack(
            URLRouter(testui.routing.websocket_urlpatterns)
        )
    ),
})
```

#### WebSocket 路由

```python

```

#### LoggingConsumer — 日志流消费者

`LoggingConsumer` 负责在 WebSocket 连接建立后，接收来自 Django 后端的日志消息并实时推送给所有连接的浏览器客户端：

```python
# testcase/consumers.py
import json
from channels.generic.websocket import WebsocketConsumer
from asgiref.sync import async_to_sync

class LoggingConsumer(WebsocketConsumer):
    def connect(self):
        # 将当前连接加入 "v2g_logging" 频道组
        self.room_group_name = 'v2g_logging'
        async_to_sync(self.channel_layer.group_add)(
            self.room_group_name, self.channel_name
        )
        self.accept()

    def receive(self, text_data):
        """接收浏览器端消息（JSON），转发至频道组"""
        text_data_json = json.loads(text_data)
        async_to_sync(self.channel_layer.group_send)(
            self.room_group_name, text_data_json
        )

    def log_message(self, event):
        """接收频道组广播的消息，发送给 WebSocket 客户端"""
        self.send(text_data=json.dumps(event))
```

### 2.7 测试执行引擎

#### 2.7.1 ExecTestcase — 多线程执行器

`testcase/execute_tc.py` 中的 `ExecTestcase` 继承自 `threading.Thread`，以独立线程运行每个测试用例。它通过 `subprocess.Popen` 调用编译后的 Titan 测试程序，并实时捕获标准输出：

```python
# testcase/execute_tc.py
class ExecTestcase(threading.Thread):
    def __init__(self, testcase, v2g_cfg, slac_cfg, secc_ip="ff02::1", task_id=None):
        ...
        self.handle = None
        super().__init__()

    def __log(self, msg, status='none'):
        """将每一行输出通过 Channels 广播至 WebSocket"""
        channel_layer = get_channel_layer()
        async_to_sync(channel_layer.group_send)(
            'v2g_logging',
            {'status': status, 'type': 'log.message',
             'message': msg, 'task_id': self.task_id}
        )

    def run(self) -> None:
        # 启动 Titan 测试程序（TTCN-3 运行时）
        self.handle = subprocess.Popen(
            [self.path, self.tc_name, "I",
             self.v2g_cfg_path, self.slac_cfg_path, self.secc_ip],
            stdout=subprocess.PIPE,
            stderr=subprocess.STDOUT,
            universal_newlines=True
        )
        # 逐行读取输出并实时推送
        while self.handle.poll() is None:
            for line in iter(self.handle.stdout.readline, ''):
                self.__log(line)
        # 程序结束后根据返回码更新数据库状态
        self._update_testcase_status()
```

#### 2.7.2 TaskQueueManager — 任务调度器

`TaskQueueManager` 是一个**单例模式**的任务队列管理器，负责控制并发数量（默认最多 3 个测试并行执行）：

```python
# testcase/execute_tc.py
class TaskQueueManager:
    """单例 — 任务队列管理器"""
    _tasks = {}           # 所有任务（task_id -> task_info）
    _running_tasks = {}   # 运行中的任务
    _max_concurrent = 3  # 最大并发数（来自 settings.MAX_CONCURRENT_TESTS）

    @classmethod
    def submit_task(cls, testcase, v2g_cfg_path, slac_cfg_path, secc_ip, priority=5):
        task_id = str(uuid.uuid4())
        if len(cls._running_tasks) < cls._max_concurrent:
            # 有空余槽位，立即启动
            exec_thread = ExecTestcase(testcase, ..., task_id=task_id)
            exec_thread.start()
            cls._running_tasks[task_id] = exec_thread
        else:
            # 队列已满，加入待执行队列（按优先级排序）
            cls._pending_tasks.put((priority, task_id))
            # 启动调度器线程
            if not cls._scheduler_thread.is_alive():
                cls._scheduler_thread.start()
        return task_id

    @classmethod
    def _scheduler_loop(cls):
        """后台调度线程：监控运行中任务，完成后自动补填待执行任务"""
        while True:
            if cls._pending_tasks.not_empty:
                if len(cls._running_tasks) < cls._max_concurrent:
                    priority, task_id = cls._pending_tasks.get()
                    # 取出并启动下一个任务
                    ...

    @classmethod
    def cancel_task(cls, task_id):
        """取消任务：杀死运行中的线程或从待执行队列移除"""
        if task_id in cls._running_tasks:
            cls._running_tasks[task_id].terminate()
            del cls._running_tasks[task_id]
```

### 2.8 Titan TTCN-3 编译器控制

`testcase/titan_engine.py` 封装了对远程 Titan TTCN-3 编译/执行服务器的控制逻辑，通过 SSH 协议（基于 Paramiko）与 Titan 服务器通信：

```python
# testcase/titan_engine.py
class TitanEngine:
    def __init__(self):
        self.ssh_client = get_ssh_client()       # SSH 连接池管理
        self.workspace = settings.TITAN_WORKSPACE # 远程工作目录
        self.compiler = settings.TITAN_COMPILER  # 编译器路径 (ttcn3_compiler)
        self.executor = settings.TITAN_EXECUTOR   # 执行器路径 (ttcn3_start)

    def compile_code(self, code, project_name=None, main_module=None):
        """通过 SSH 在远程服务器上编译 TTCN-3 代码"""
        # 1. 在远程创建项目目录
        # 2. 通过 SFTP 上传 .ttcn 源文件
        # 3. 执行编译命令: ttcn3_compiler MainModule.ttcn
        # 4. 返回编译输出（成功/错误信息）
        ssh = self.ssh_client.get_connection()
        _, stdout, stderr = ssh.exec_command(
            f"cd {self.workspace}/{project_name} && {self.compiler} {main_module}.ttcn"
        )
        return stdout.read().decode() + stderr.read().decode()

    def execute_test(self, project_path, main_module, config_file=None, secc_ip="ff02::1"):
        """通过 SSH 启动 Titan 测试执行"""
        cmd = f"cd {project_path} && {self.executor} {main_module} {config_file} {secc_ip}"
        ssh = self.ssh_client.get_connection()
        stdin, stdout, stderr = ssh.exec_command(cmd)
        return stdout.read().decode() + stderr.read().decode()
```

### 2.9 LLM 辅助脚本生成

`testcase/llm_client.py` 封装了 OpenAI GPT-4 API 调用，用于根据用户输入的自然语言测试意图自动生成 TTCN-3 测试脚本：

```python
# testcase/llm_client.py
class LLMClient:

    def generate_ttcn3_script(self, test_intent, test_type="CMN"):

        System prompt 中包含 TTCN-3 编码规范和最佳实践指导。
        """
        system_prompt = """你是 ISO 15118 协议 TTCN-3 测试脚本生成专家。
        请严格遵循以下规范生成测试代码..."""
        response = self.client.chat.completions.create(
            model=self.model,
            messages=[
                {"role": "system", "content": system_prompt},
                {"role": "user",   "content": test_intent}
            ]
        )
        return response.choices[0].message.content
```

Pinia 是 Vue 3 官方推荐的新一代状态管理库，提供了类型安全的 Store 定义方式。项目中所有跨组件共享的状态和业务逻辑集中管理在 `testStore` 中：

```javascript
// src/stores/testStore.js
import { defineStore } from 'pinia'
import { api } from '../api/index'

export const useTestStore = defineStore('test', {
    state: () => ({
        summaryInfo: [],           // 首页统计数据
        testcaseList: [],          // 测试用例列表

            pics: {},
            pixit: {},
            timer: {},
            slac: {}

            name: '',

            task_id: null
        },

            running: [],
            pending: [],
            maxConcurrent: 3

    actions: {

        async act_get_testcases(queryParams) {
```

### 3.5 Axios HTTP 客户端封装

所有前后端 HTTP 通信经由 `api/index.js` 中定义的 Axios 实例进行。该实例配置了请求/响应拦截器，实现统一错误处理、请求超时控制和 Bearer Token 认证：

```javascript
// src/api/index.js
import axios from 'axios'
import { ElMessage } from 'element-plus'

const api = axios.create({
    baseURL: '/api/v1',   // Vite 代理会将此路径转发至 Django (http://localhost:8000)
    timeout: 30000,
    headers: { 'Content-Type': 'application/json' }
})

// 请求拦截器：可在此处统一添加认证 Token
api.interceptors.request.use(config => {
    const token = localStorage.getItem('auth_token')
    if (token) {
        config.headers.Authorization = `Bearer ${token}`
    }
    return config
})

// 响应拦截器：统一处理错误提示
api.interceptors.response.use(
    response => response,
    error => {
        ElMessage.error(error.response?.data?.message || '请求失败')
        return Promise.reject(error)
    }
)

// 各业务 API 方法
export const getTestcases = (params) => api.get('/testcases/', { params })

export const getTestcase = (id) => api.get(`/testcases/${id}/`)

export const executeTestcase = (id, config, secc_ip) =>
    api.put(`/execute/${id}/`, { config, secc_ip })

export const generateTestScript = (intent, msgType) =>
    api.post('/llm/generate/generate/', { intent, msg_type: msgType })

export const compileTTCNCode = (code, projectName) =>
    api.post('/ttcn/compile/compile/', { code, project_name: projectName })

export const compileAndExecuteTTCN = (code, projectName, mainModule, configFile, seccIp) =>
    api.post('/ttcn/execute/compile_and_execute/', {
        code, project_name: projectName, main_module: mainModule,
        config_file: configFile, secc_ip: seccIp
    })

export const getQueueStatus = () => api.get('/execute/', { params: { action: 'queue_status' } })

export const getTaskStatus = (taskId) =>
    api.get('/execute/', { params: { action: 'task_status', task_id: taskId } })

export const cancelTask = (taskId) =>

export default api
```

## 四、前后端交互机制

### 4.1 REST API — 主通信通道

前端通过 Axios 封装的所有业务请求统一发往 `/api/v1/` 前缀下的端点。Vite 开发服务器的代理配置确保这些请求被转发至 Django 后端的 8000 端口。以下是核心交互流程的典型序列：

**测试执行流程（HTTP）**：

```
1. 前端 TestcaseExecute.vue
      │  PUT /api/v1/execute/{id}/
      │  Body: { config: {pics, pixit, timer, slac}, secc_ip }
      ▼
2. Django TestcaseExecute.update()
      │  解析 config，生成 v2g_config.json 和 slac_config.json
      │  调用 TaskQueueManager.submit_task()
      ▼
3. TaskQueueManager
      │  检查并发数：若 < max_concurrent -> 立即启动 ExecTestcase 线程
      │                   若 = max_concurrent -> 加入待执行队列
      ▼
4. ExecTestcase.run() (后台线程)
      │  subprocess.Popen 启动 Titan 测试程序
      │  每读一行 stdout -> channel_layer.group_send('v2g_logging', ...)
      ▼
5. Django Response
      ◄  { status: "OK", task_id: "uuid" }
```

**WebSocket 日志流（实时推送）**：

```
前端 Pinia Store.initWebSocket()
      │
      ├─► ws://localhost:8080/ws/logging/
      │       (Vite 代理)  ws://localhost:8000/ws/logging/
      │
      ▼
Django LoggingConsumer
      │
      ├─► connect():   async_to_sync(channel_layer.group_add)('v2g_logging', channel_name)
      │
      └─► log_message():  self.send(json.dumps(event))  ──► 推送至浏览器

前端 loggingSocket.onmessage:
      │
      ▼
store.mutate_update_logging_data(recv.message)
      │
      ▼
页面 <pre> 日志区自动追加新行（实时刷新）
```

## 五、技术特点总结

| 维度 | 技术选型 | 设计考量 |
|------|---------|---------|
| **前后端分离** | Vite + Django | 前端独立构建，与后端仅通过 REST API 通信，便于并行开发和部署 |
| **实时通信** | Django Channels + WebSocket | 测试执行日志需要毫秒级实时推送，HTTP 轮询无法满足需求 |
| **状态管理** | Pinia | 替代 Vuex，更轻量且对 TypeScript 支持更好 |
| **并发控制** | `threading.Thread` + 优先队列 | 避免引入 Celery/Redis 等重型中间件，降低部署复杂度 |
| **远程执行** | Paramiko SSH | Titan 编译器运行在专用远程服务器上，通过 SSH 协议控制 |
| **API 文档** | DRF + drf_yasg | 自动从 ViewSet 和 Serializer 生成 Swagger UI，降低前后端对接成本 |
| **AI 集成** | OpenAI API + LangChain 思想 | 将自然语言测试意图转换为 TTCN-3 代码，降低测试用例编写门槛 |
| **协议测试** | TTCN-3 + Titan | ISO 15118 国际标准规定的官方测试描述语言，Titan 为其参考实现 |

> 本项目将 Django 的成熟生态（ORM、REST、认证）与 Vue 3 的现代响应式理念相结合，通过 WebSocket 实现了传统 HTTP 协议难以支持的实时日志流场景，是电动汽车充电协议测试领域一次成功的全栈技术实践。
