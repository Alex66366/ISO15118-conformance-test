## Mechanical SOP: Every V2G Message Exchange (Pure Static Data-Driven Pipeline)

For EVERY V2G application message (SupportedAppProtocol through SessionStop), execute these four steps in strict order:

  STEP 1: Lookup JSON -- Read exi_payload_library.json. Record:
    - `wire_hex`: the canonical pre-encoded wire bytes
    - `is_dynamic`: if true, SessionID will be patched automatically by the C++ adapter
    - `feature_pattern`: anchor bytes for message type identification
    - `dynamic_field_offsets`: byte offsets for SessionID, ResponseCode, EVSEID

  STEP 2: Locate template -- Find `md_CMN_{Msg}Req_001` (send) in SECC_CmnTemplates.ttcn.
    For receive, use the **lenient template** `{ msgRes := ? }` -- the C++ StaticExiDecoder
    extracts dynamic field values from wire bytes and the lenient template accepts any values.

  STEP 3: Send via structured union ONLY
    ```ttcn3
    pt_V2G_TCP_TLS_ALM_SECC_Port.send({ msgType := md_CMN_MsgReq_001 })
    ```
    PROHIBITED: raw octetstrings, int2oct for V2GTP headers, hex literals on TCP port.

  STEP 4: Receive and set verdict
    ```ttcn3
    // Use lenient template -- StaticExiDecoder extracts SessionID, ResponseCode, EVSEID from wire
    pt_V2G_TCP_TLS_ALM_SECC_Port.receive({ resType := ? })
    ```
    Stop timer before setverdict in non-timeout branches. End function with `return getverdict;`.

**SDP messages ONLY (UDP port):** Use raw octetstrings.
  pt_V2G_UDP_SDP_Port.send('01FE9000000000021000'O) -- this is CORRECT for SDP.

### NEGATIVE CONSTRAINTS (MUST NOT)

- MUST NOT use int2oct, '01'O, 'FE'O, '8001'O in TTCN-3 for V2GTP header construction
- MUST NOT send raw octetstrings to the TCP port for V2G application messages
- MUST NOT use openv2g encoder or X-Macro mapping -- StaticExiDecoder handles encoding/decoding via static JSON patterns
- MUST NOT use V2G_MessageUnion with manual EXI encoding -- the adapter handles it
- MUST NOT hardcode ResponseCode, SessionID, or EVSEID values in receive templates -- use lenient `?` template

## Core Generation Principles

### Principle 1: V2G Message Exchange via Structured Union
The V2G_TCP_TLS_Port uses structured message types (`V2G_MessageUnion`) for EXI application messages.
- V2G application messages: send/receive structured TTCN-3 templates
- SDP messages (UDP): raw octetstring protocol -- no EXI encoding needed
- The C++ port adapter (V2G_TCP_TLS_Port) calls ExiCodecAdapter to encode/decode transparently

### Principle 2: Precondition Chain Position Semantics
The position in precondition_chain determines behavior:
- Position 1 (first): SDP discovery via UDP multicast
- Position 2 (second): SupportedAppProtocol exchange
- Position 3+ (middle): Subsequent V2G messages
- Last position: The message under test (sends + expects response in alt block)

### Principle 3: Timer Must Be Stopped Before setverdict
When you call timer.start(value), you MUST call timer.stop in every branch
that does NOT time out. The timeout branch does NOT call stop.

### Principle 4: Test Behavior Always Ends With return getverdict

---

## Verdict Logic Decision Tree

FOR EACH test_type:

GoodCase:
    receive matches expected response  ->  setverdict(pass, "...")
    receive unexpected response        ->  setverdict(fail, "unexpected response")
    timer timeout                     ->  setverdict(inconc, "timeout")
    connection closed by SUT          ->  setverdict(fail, "connection lost")

BadCase:
    receive indicates error/rejection  ->  setverdict(pass, "SUT correctly rejected")
    receive indicates acceptance       ->  setverdict(fail, "SUT should reject")
    timeout                            ->  setverdict(pass, "SUT correctly ignored")
    connection closed by SUT           ->  setverdict(pass, "SUT correctly closed")

## Precondition Function Generation Patterns

### Pattern: InitConfiguration (Position 1: Port Mapping + SDP Discovery)

**CRITICAL:** This is ALWAYS position 1. Without SDP discovery, the SECC never opens its TCP port, causing TCP timeout in the test. Use the COMPLETE implementation below (not a stub).

```ttcn3
module PreConditions_InitConfig {
    import from SECC_TestSystem all;

    function f_SECC_CMN_PR_InitConfiguration_001()
        runs on SECCTester
        return verdicttype
    {
        // Phase A: Port mapping
        map(mtc:pt_V2G_TCP_TLS_ALM_SECC_Port, system:pt_V2G_TCP_TLS_ALM_SECC_Port);
        map(mtc:pt_V2G_UDP_SDP_Port, system:pt_V2G_UDP_SDP_Port);

        // Phase B: SDP Discovery (mandatory -- SECC must be found before TCP connect)
        // V2GTP header: version=01, inv=FE, payloadType=9000(SDP), length=4, body=2100
        var octetstring sdp_req := '01FE9000000000021000'O;
        pt_V2G_UDP_SDP_Port.send(sdp_req);

        timer t_sdp;
        t_sdp.start(5.0);

        alt {
            [] pt_V2G_UDP_SDP_Port.receive {
                t_sdp.stop;
                log("SDP discovery: SECC found via UDP multicast");
            }
            [] t_sdp.timeout {
                log("SDP discovery: timeout, proceeding anyway (SIL mode)");
            }
        }

        log("InitConfiguration complete, SDP discovery done");
        return pass;
    }
}
```

### Pattern: SupportedAppProtocol (Position 2: AppProtocol Negotiation)

This is the FIRST V2G application message exchange after SDP. It negotiates the protocol schema (ISO 15118-2 or DIN SPEC 70121). SessionID is initialized to 0000000000000000 for a new session.

```ttcn3
module f_SECC_CMN_PR_SupportedAppProtocol_001 {
    import from SECC_TestSystem all;
    import from SECC_Types all;
    import from SECC_CmnTemplates all;
    import from SECC_Constants all;

    function f_SECC_CMN_PR_SupportedAppProtocol_001()
        runs on SECCTester
        return verdicttype
    {
        timer tc_V2G_EVCC_Msg_Timer := PX_SECC_CMN_Message_Timeout;

        log("Phase B: Sending SupportedAppProtocolReq via structured union template...");

        tc_V2G_EVCC_Msg_Timer.start(PX_SECC_CMN_Message_Timeout);

        // STEP 3: Send via structured union -- ExiCodecAdapter encodes
        pt_V2G_TCP_TLS_ALM_SECC_Port.send(
            { supportedAppProtocolReq := md_CMN_SupportedAppProtocolReq_001 }
        );

        // STEP 4: Receive and set verdict
        alt {
            [] pt_V2G_TCP_TLS_ALM_SECC_Port.receive(
                { supportedAppProtocolRes := md_CMN_SupportedAppProtocolRes_001 }
            ) {
                tc_V2G_EVCC_Msg_Timer.stop;
                log("SupportedAppProtocolRes received: protocol negotiation complete");
                log("SessionID initialized to 0000000000000000 (new session)");
                setverdict(pass, "SupportedAppProtocol exchange successful");
            }
            [] pt_V2G_TCP_TLS_ALM_SECC_Port.receive(
                { supportedAppProtocolRes := md_CMN_SupportedAppProtocolRes_002 }
            ) {
                tc_V2G_EVCC_Msg_Timer.stop;
                setverdict(fail, "SECC rejected the protocol negotiation");
            }
            [] tc_V2G_EVCC_Msg_Timer.timeout {
                setverdict(inconc, "Timeout waiting for SupportedAppProtocolRes");
            }
        }

        return getverdict;
    }
}
```

### Pattern: SessionSetup Test Behavior (Last Position: Message Under Test)

```ttcn3
module f_SECC_CMN_TB_VTB_V2GTPSessionSetup_001 {
```
