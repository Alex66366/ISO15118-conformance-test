### MANDATORY: No `?` with `&` in Octetstring Templates

In TTCN-3 octetstring pattern matching, the `?` (AnyValue) wildcard CANNOT be concatenated with the `&` operator. This is a language restriction, not a style preference.

**FORBIDDEN (will NOT compile):**
```ttcn3
template octetstring t := '01'O & 'FE'O & ?;        // COMPILE ERROR
template octetstring t := '01'O & ? & '8001'O;       // COMPILE ERROR
```

**CORRECT -- Use receive(?) with manual field checks in alt branch:**
```ttcn3
alt {
    [] pt_V2G_TCP_TLS_ALM_SECC_Port.receive(?) -> value v_resp {
        tc_V2G_EVCC_Msg_Timer.stop;
        if (lengthof(v_resp) >= 8 and substr(v_resp, 0, 1) == '01'O
            and substr(v_resp, 1, 1) == 'FE'O and substr(v_resp, 2, 2) == '8002'O) {
            setverdict(pass, "Valid response received");
        } else {
            setverdict(fail, "Response has wrong payload type");
        }
    }
    [] tc_V2G_EVCC_Msg_Timer.timeout {
        setverdict(inconc, "Timeout waiting for response");
    }
}
```

**CORRECT -- Use exact concatenation (no `?`):**
```ttcn3
// CRITICAL: Use a REAL, valid ISO 15118-2 EXI octetstring -- NEVER '0022'O or dummy placeholders.
// Dummy EXI will crash the SECC's EXI decoder, causing TCP connection drops and 'inconc' verdict.
// NOTE: EXI payload hex string MUST have an even number of hex characters. If odd, pad with '0' or '00'.
var octetstring exi_payload := '8000EBAB9371D34B9B79D189A98989C1D191D191818999D26B9B3A232B30020000000001B75726E3A64696E3A37303132313A323031323A4D73674465660040000000880000'O; // Valid SupportedAppProtocolReq EXI (140 bytes, 280 hex chars)
template octetstring t := '01'O & 'FE'O & '8001'O & int2oct(lengthof(exi_payload), 4) & exi_payload;
```

**REMEMBER:** In TTCN-3, `?` inside a receive pattern with `&` concatenation is ambiguous -- it can match varying numbers of bytes depending on the pattern prefix length. Always use `receive(?)` with manual `substr()`/`lengthof()` checks inside the alt branch for V2GTP field validation.

### Component and Port Mapping
- In `map()`/`unmap()` calls, use the port instance names from generation_plan:

  - Correct: `module PreConditions_TCPConnected { function f_SECC_CMN_PR_TCP_Connected_001() ... }`
  - WRONG: `module f_SECC_CMN_PR_TCP_Connected_001 { function f_SECC_CMN_PR_TCP_Connected_001() ... }`

  - The pipeline will automatically inject the correct `import from <module_name> all;` statements into the aggregator modules.

TTCN-3 does NOT re-export symbols imported through intermediate modules. The main testcase module MUST directly import from EVERY individual function module it calls. Do NOT rely solely on the aggregator module for imports.

    import from f_SECC_CMN_PO_ShutdownConfiguration_001 all; // direct!
    // ...
}
```

**WRONG (main TC file):**
```ttcn3
module TC_SECC_CMN_VTB_V2GTPHeader_001 {
    import from SECC_TestSystem all;
    import from PreConditions_SECC_15118_2 all;   // transitive ONLY - INVALID

### Precondition Function Parameters
- {PRECON_PARAMS_BLOCK}
- If a precondition function returns verdicttype, you MUST store it in preConVerdict and check it before Phase C

### Postcondition Function Parameters
- {POSTCON_PARAMS_BLOCK}
- PostConditions MUST be called regardless of preConVerdict value (Phase D runs unconditionally)

### Timer
- EVERY alt branch that receives a message MUST call {timer}.stop BEFORE setverdict
- Timer timeout branch does NOT call stop (it already expired)

### Verdict Logic
- GoodCase: pass on valid response, fail on invalid, inconc on timeout
- BadCase: pass on rejection/close/timeout, fail on acceptance of invalid input

### V2GTP Header
- Always wrap V2G messages in V2GTP:
  - protocolVersion='01'O, invProtocolVersion='FE'O
  - payloadType varies by message type:
    - **SDP discovery**: payloadType='9000'O
    - **V2G application messages** (SessionSetup, ServiceDiscovery, etc.): payloadType='8001'O
  - payloadLength: MUST be a 4-byte octetstring, e.g. `int2oct(payloadSize, 4)`
  - DO NOT use 'omit' for payloadLength (it is not optional)
- **Port Type Constraint (CRITICAL)**: The `V2G_TCP_TLS_Port` port type is defined as `out octetstring; in octetstring;`.
  This means you MUST send and receive `octetstring`, NOT record types or template types.
  - Correct: `{port_name}.send('01'O & 'FE'O & '8001'O & int2oct(len, 4) & payload)` (octetstring concatenation)
  - WRONG: `{port_name}.send(someRecordTemplate)` — record types are not allowed
  - WRONG: `{port_name}.receive(someRecordTemplate)` — port only accepts octetstring
  - Correct: `{port_name}.receive(?)` (wildcard matching, then check bytes manually with substr)

module TC_SECC_CMN_VTB_V2GTPSessionSetup_001 {

    // === Imports (MANDATORY: include direct imports for all function modules) ===
    import from SECC_TestSystem all;
    import from SECC_Types all;
    import from SECC_CmnTemplates all;
    import from SECC_Constants all;

    // Aggregator imports
    import from PreConditions_SECC_15118_2 all;
    import from PostConditions_SECC_15118_2 all;

    // Direct imports for all called functions (required -- TTCN-3 does NOT re-export transitively)
    import from f_SECC_CMN_PR_InitConfiguration_001 all;
    import from f_SECC_CMN_PR_Binding_001 all;
    import from f_SECC_CMN_PO_InitialState_001 all;
    import from f_SECC_CMN_PO_ShutdownConfiguration_001 all;

    // === Test Behavior Function ===
    function f_SECC_CMN_TB_VTB_V2GTPSessionSetup_001()
        runs on SECCTester
        return verdicttype
    {
        timer tc_V2G_EVCC_Msg_Timer := PX_SECC_CMN_Message_Timeout;

        // CRITICAL: Use a REAL, valid ISO 15118-2 EXI octetstring.
        // Dummy EXI placeholders crash the SECC EXI decoder and cause TCP drops.
        // NOTE: EXI payload hex string MUST have an even number of hex characters. If odd, pad with '0' or '00'.
        var octetstring session_setup_req := '8000EBAB9371D34B9B79D189A98989C1D191D191818999D26B9B3A232B30020000000001B75726E3A64696E3A37303132313A323031323A4D73674465660040000000880000'O; // Valid SupportedAppProtocolReq EXI (140 bytes, 280 hex chars)
        var integer payload_len := lengthof(session_setup_req);
        var octetstring v2gtp_msg := '01'O & 'FE'O & '8003'O
                                    & int2oct(payload_len, 4)
                                    & session_setup_req;

        tc_V2G_EVCC_Msg_Timer.start(PX_SECC_CMN_Message_Timeout);
        pt_V2G_TCP_TLS_ALM_SECC_Port.send(v2gtp_msg);

        alt {
            // Expected: Valid SessionSetupRes with correct V2GTP header
            [] pt_V2G_TCP_TLS_ALM_SECC_Port.receive(?) -> value v_resp {
                tc_V2G_EVCC_Msg_Timer.stop;
                // Manually check V2GTP header fields (cannot use ? with & in templates)
                if (lengthof(v_resp) >= 8 and substr(v_resp, 0, 1) == '01'O
                    and substr(v_resp, 1, 1) == 'FE'O and substr(v_resp, 2, 2) == '8004'O) {
                    setverdict(pass, "SECC responded with SessionSetupRes");
                } else {
                    setverdict(fail, "SECC sent unexpected message");
                }

                setverdict(inconc, "SECC did not respond within timeout");
            }
        }

        return getverdict;
    }

    // === Testcase ===

        f_SECC_CMN_PR_InitConfiguration_001();

            setverdict(inconc);
        }

        // Phase D: Post Conditions (unconditional cleanup)
        f_SECC_CMN_PO_InitialState_001();
        f_SECC_CMN_PO_ShutdownConfiguration_001();
    }

## Core Generation Principles

### Principle 1: Ports Are Raw Byte Pipes
The V2G_TCP_TLS_Port and V2G_UDP_SDP_Port types are declared as `{ out octetstring; in octetstring; }`.
- ALL messages are octetstrings. No record types flow through ports.
- Sending: construct octetstring via concatenation (&), call .send()
- Receiving: use wildcard matching (?), e.g., `.receive('01'O & 'FE'O & ?)`
- DO NOT send record templates through ports -- they will not compile

### Principle 2: Precondition Chain Position Semantics
The position in precondition_chain determines behavior:
- Position 1 (first): SDP discovery via UDP multicast
- Position 2 (second): SupportedAppProtocol exchange
- Position 3+ (middle): Subsequent V2G messages
- Last position: The message under test (sends + expects response in alt block)

### Principle 3: Timer Must Be Stopped Before setverdict
When you call timer.start(value), you MUST call timer.stop in every branch
that does NOT time out. The timeout branch does NOT call stop.

### Principle 4: Test Behavior Always Ends With return getverdict

---

## Verdict Logic Decision Tree

FOR EACH test_type:

GoodCase:
    receive matches expected response  ->  setverdict(pass, "...")
    receive unexpected response        ->  setverdict(fail, "unexpected response")
    timer timeout                     ->  setverdict(inconc, "timeout")
    connection closed by SUT           ->  setverdict(fail, "connection lost")

BadCase:
    receive indicates error/rejection  ->  setverdict(pass, "SUT correctly rejected")
    receive indicates acceptance       ->  setverdict(fail, "SUT should reject")
    timeout                            ->  setverdict(pass, "SUT correctly ignored")
    connection closed by SUT           ->  setverdict(pass, "SUT correctly closed")

## Precondition Function Generation Patterns

### Pattern: InitConfiguration (Position 1: Port Mapping + SDP Discovery)

**CRITICAL:** This is ALWAYS position 1. Without SDP discovery, the SECC never opens its TCP port, causing TCP timeout in the test. Use the COMPLETE implementation below (not a stub).

```ttcn3
module f_SECC_CMN_PR_InitConfiguration_001 {
    import from SECC_TestSystem all;

    function f_SECC_CMN_PR_InitConfiguration_001()
        runs on SECCTester
        return verdicttype
    {
        // Phase A: Port mapping
        map(mtc:pt_V2G_TCP_TLS_ALM_SECC_Port, system:pt_V2G_TCP_TLS_ALM_SECC_Port);
        map(mtc:pt_V2G_UDP_SDP_Port, system:pt_V2G_UDP_SDP_Port);

        // Phase B: SDP Discovery (mandatory -- SECC must be found before TCP connect)
        // V2GTP header: version=01, inv=FE, payloadType=9000(SDP), length=4, body=2100
        var octetstring sdp_req := '01FE9000000000021000'O;
        pt_V2G_UDP_SDP_Port.send(sdp_req);

        timer t_sdp;
        t_sdp.start(5.0);

        alt {
            [] pt_V2G_UDP_SDP_Port.receive {
                t_sdp.stop;
                log("SDP discovery: SECC found via UDP multicast");
            }
            [] t_sdp.timeout {
                log("SDP discovery: timeout, proceeding anyway (SIL mode)");
            }
        }

        log("SIL mode: InitConfiguration complete, SDP discovery done");
        return pass;
    }
}
```

**CRITICAL RULES:**
- Do NOT omit the SDP discovery block
- Do NOT use `payloadType='8001'O` for SDP -- use `payloadType='9000'O`
- The SDP body `2100` means "request SECC IPv6 address"
- After SDP, the C++ port adapter reads the SECC IP/port from the SDP response and uses it for TCP connections
- In SIL mode, SDP timeout is non-fatal -- proceed anyway

### Pattern: V2GTP Message Send (Last Position: Message Under Test)
```ttcn3
module TestBehavior_V2G {
    function f_{SUT}_CMN_TB_VTB_{MsgType}_{SeqNo}()
        runs on {SUT}Tester
        return verdicttype
    {
        timer tc_msg := PX_SECC_CMN_Message_Timeout;
        tc_msg.start;
        // CRITICAL: Use a REAL, valid ISO 15118-2 EXI octetstring -- NEVER a dummy placeholder.
        // Dummy EXI (e.g. '0022'O) crashes the SECC EXI decoder and drops the TCP connection.
        // NOTE: EXI payload hex string MUST have an even number of hex characters. If odd, pad with '0' or '00'.
        var octetstring exi_payload := '8000EBAB9371D34B9B79D189A98989C1D191D191818999D26B9B3A232B30020000000001B75726E3A64696E3A37303132313A323031323A4D73674465660040000000880000'O;  // Valid SupportedAppProtocolReq EXI (140 bytes, 280 hex chars)
        var integer payload_len := lengthof(exi_payload);
        var octetstring v2gtp := '01'O & 'FE'O & '8001'O &
                                 int2oct(payload_len, 4) & exi_payload;
        pt_V2G_TCP_TLS_ALM_{SUT}_Port.send(v2gtp);
        alt {
            [] pt_V2G_TCP_TLS_ALM_{SUT}_Port.receive('01'O & 'FE'O & '8002'O & ?) -> value v_resp {
                tc_msg.stop;
                if (lengthof(v_resp) >= 8) {
                    setverdict(pass, "Valid response received");
                } else {
                    setverdict(fail, "Malformed response");
                }
            }
            [] pt_V2G_TCP_TLS_ALM_{SUT}_Port.receive(?) {
                tc_msg.stop;
                setverdict(fail, "Unexpected message received");
            }
            [] tc_msg.timeout {
                setverdict(inconc, "Timeout waiting for response");
            }
        }
        return getverdict;
