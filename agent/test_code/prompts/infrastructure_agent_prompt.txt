## Fail-Fast Error Indicator (Sprint 3, 2026-07-11) — MANDATORY

**Why this exists:** Pre-Sprint-3, when the EXI microservice returned a
`DECODE ERROR` (schema mismatch, framing corruption, malformed SECC bytes,
etc.), the C++ V2G_TCP_TLS_Port adapter **silently dropped the message**.
The TTCN-3 test case then waited the full per-TC message timeout (default
**20 minutes**) before `setverdict(fail)`. This burned enormous compute
time on tests that could never succeed.

Sprint 3 introduces a **typed `error_indicator` alternative** on the
receive side. The C++ adapter now pushes a `V2G_ErrorInfo` record into
the port queue, so TITAN matches it within milliseconds and the test
case sets `verdict=fail` immediately.

### Type Definition (already in SECC_Types / Types_SECC_15118_2.ttcn)

```ttcn3
type record V2G_ErrorInfo {
    charstring  source,          // "exi_decode" | "v2gtp_framing"
                                  //   | "exi_payload_too_large" | "exi_service_unavailable"
    charstring  detail,          // raw diagnostic (microservice response or stderr).
                                  //   Named `detail` (not `message`) because `message`
                                  //   is a reserved keyword in TTCN-3 (used in
                                  //   inter-module communication).
    charstring  namespace_uri optional  // e.g. "urn:iso:15118:2:2013:MsgDef"; omit if N/A
}
```

### MANDATORY alt-branch on every V2G_TCP_TLS_Port.receive

**Every** receive on `pt_V2G_TCP_TLS_ALM_SECC_Port` MUST include an
`error_indicator` branch FIRST in the alt-block (before any
`{ raw := ... }` or typed-pattern branches), so the fail-fast path
takes priority over a noisy success-side receive.

**Canonical alt-block template** (every V2G behavior function):

```ttcn3

    // FAIL-FAST: C++ adapter detected DECODE ERROR / framing / payload-too-large.
    // MUST be the FIRST branch in every alt-block that includes a
    // pt_V2G_TCP_TLS_ALM_SECC_Port.receive(...).
    [] pt_V2G_TCP_TLS_ALM_SECC_Port.receive({ error_indicator := ? })
        -> value v_err {

            "C++ adapter error_indicator: ",
            v_err.error_indicator.source,

3. The V2GTP port (V2G_TCP_TLS_Port, v3 Dumb Terminal) handles all EXI encoding/decoding by forwarding JSON to the Python microservice at localhost:9000. The microservice uses Siemens EXIficient (py4j + EXICodec.jar) to produce correct EXI bytes. The C++ adapter adds the V2GTP header and sends to SECC. The `V2G_MessageUnion` TTCN-3 type is used for compile-time type safety only.

### EXI Microservice (v3 Universal EXI Bridge)

The Python microservice runs at localhost:9000. Protocol (TCP, custom framing):
  Encode:  "ENCODE\n<namespace>\n<json>\n\n"  ->  "OK\n<exi_hex>\n\n"
  Decode:  "DECODE\n<namespace>\n<exi_hex>\n\n"  ->  "OK\n<json>\n\n"

Startup (before running TestExecutable):
  cd shared_infrastructure/exi_microservice
  python3 exi_microservice.py &
  # Or: ./start_exi_service.sh

Required: EXICodec.jar (download from https://github.com/EXIficient/exificient)
Required: py4j (pip install py4j)

Example usage in TTCN-3 templates:
```ttcn3
// ✅ CORRECT (Sprint 3): Structured-union send side on TCP port.
// The C++ V2G_TCP_TLS_Port adapter forwards the typed union selection + JSON
// to the Python microservice at localhost:9000, prepends the V2GTP header,
// and sends to SECC. PascalCase element names are enforced automatically by
// MOXy from the XSD, so we never see UnmarshalException.
//
// NOTE on PascalCase: If you ever edit a `var charstring ... := "{\"sessionID\":...}"` style
// literal, ALWAYS use PascalCase keys: `SessionID`, `EVCCID`, `PaymentServiceSelectionReq`, etc.
// The word `sessionID` or `evccID` inside a JSON string is a bug. The pipeline's
// `sanitize_v2g_json_keys` sanitizer will fix it automatically, but correct-first saves cycles.
pt_V2G_TCP_TLS_ALM_SECC_Port.send(char2oct(json_req));

// ✅ ALSO CORRECT (Sprint 3): Receive via the typed V2G_PortMessage union (Sprint 3).
//   The receive path is split-direction Dumb Terminal (in V2G_PortMessage,
//   not V2G_MessageUnion). The receive port has ONLY two variants:
//     { raw := ? }            — successfully-decoded JSON bytes (TTCN-3 then
//                                dispatches via oct2char() to typed templates).
//     { error_indicator := ? } — fail-fast error notification from the C++
//                                adapter (DECODE ERROR / framing failure /
//                                exi_service_unavailable, etc.). Immediately
//                                terminates the per-TC run with verdict=fail.
//   The pre-Sprint-3 pattern `receive({ v2g := { sessionSetupRes := ? } })`
//   is COMPILE ERROR — `v2g` is NOT a valid field on V2G_PortMessage.
alt {
    [] pt_V2G_TCP_TLS_ALM_SECC_Port.receive({ error_indicator := ? })
        -> value v_err {
        tc_V2G_SECC_Msg_Timer.stop;
        setverdict(fail,
            "C++ adapter error_indicator: ", v_err.error_indicator.source,
            ": ", v_err.error_indicator.detail);

        var octetstring resp_payload := v_msg.raw;
        var charstring  resp_json    := oct2char(resp_payload);
        log("SECC raw JSON: ", resp_json);
        // ...dispatch resp_json to typed template match in a SEPARATE alt...
        setverdict(pass);
    }
    [] tc_V2G_SECC_Msg_Timer.timeout {
        setverdict(fail, "Timed out waiting for SECC response");
    }
}
```
