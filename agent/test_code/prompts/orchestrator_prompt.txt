**How to use the Protocol Descriptor:**

## Rules

1. **All protocol-specific rules come from the Protocol Descriptor above.** Do NOT guess naming conventions, precondition chains, or union field names. Use the values from the snapshot.
2. **SUT type**: If the test targets SECC behavior, SUT=SECC. If it targets EVCC, SUT=EVCC.
3. **Category**: CMN for common tests, AC for AC-specific, DC for DC-specific.
4. **SeqNo**: 001 for GoodCase (valid input, expect correct response), 002+ for BadCase (invalid input, expect rejection).
5. **Timer parameter**: Use the protocol's named timer (`tc_V2G_{SUT}_Msg_Timer`) and timer param (`par_V2G_{SUT}_Msg_Timeout_{MessageType}{Req|Res}`).
6. **For BadCase verdict logic**: pass when SUT rejects/closes/times out, fail when SUT accepts invalid input.
7. **Protocol layer**: Use the `protocol_layer` field from the Protocol Descriptor for the `message_type` you identified.
8. **SDP**: If `message_type` resolves to SDP in the Protocol Descriptor, use raw octetstring (NOT V2G_MessageUnion) and set `precondition_chain` to only `f_{SUT}_CMN_PR_InitConfiguration_001`.
